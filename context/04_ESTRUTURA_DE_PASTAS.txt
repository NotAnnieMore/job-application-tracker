JOB APPLICATION TRACKER
PROPOSTA DE ESTRUTURA DE PASTAS

A estrutura abaixo assume:
- Next.js;
- TypeScript;
- App Router;
- Tailwind CSS;
- Supabase;
- separação entre interface, regras de negócio, acesso a dados e validação.

Esta é uma proposta inicial. Deve ser ajustada quando começarmos a implementar.

EXPLICAÇÃO DAS ÁREAS PRINCIPAIS

src/app/
Contém páginas, layouts, loading, erros e rotas.

src/components/
Contém componentes visuais reutilizáveis.

src/features/
Contém a lógica de cada domínio.
Exemplo:
- schemas;
- tipos;
- queries;
- ações;
- constantes.

src/lib/
Contém integrações e utilitários transversais.

src/config/
Contém configurações estáticas, navegação, estados e dados do site.

supabase/
Contém migrations, configuração local e dados de teste.

docs/
Regista arquitetura e decisões técnicas.

tests/
Agrupa testes por tipo.

RECOMENDAÇÃO IMPORTANTE

Evitar criar uma estrutura demasiado complexa logo no primeiro dia.

Começar apenas com:
- app;
- components;
- lib;
- features;
- supabase.

Adicionar novas pastas apenas quando existirem ficheiros suficientes que justifiquem a separação.

ESTRUTURA MÍNIMA PARA O INÍCIO

src/
|-- app/
|-- components/
|-- features/
|-- lib/
|-- types/

supabase/
|-- migrations/

docs/
|-- decisions/

Depois, a estrutura evolui conforme o projeto.
